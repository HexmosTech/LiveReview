## Invariants the port must hold

1. **`MathMode.Final == hunk.Combined`.** The step-by-step derivation must land
   on the number `git-lrc` already computed and stored. If these ever diverge,
   the port has drifted from the scoring source of truth.
   Verified here: 30.7 → 100 blast, 69.7 → 100 priority, blended 100 ×1 = 100 =
   `Combined`.
2. **Category → dimension split is the load-bearing rule.**
   `{architecture, graph}` → Blast Radius, `{duplication, code-metrics}` →
   Review Priority. Nothing else in the artifact encodes which dimension a
   signal feeds. A signal in neither set (e.g. `diff-shape`) contributes to
   *neither* subtotal.
3. **Two different symbol orderings coexist**, and conflating them silently
   reorders the Math Mode lines:
   - Math Mode (`MathModeView`) iterates `detail.Symbols` in **raw artifact
     order**.
   - The symbol carousel below the tabs sorts by **`BlastRadiusRaw` desc**.
4. **Step numbering is dynamic.** The *"add every subtotal together"* step only
   exists when more than one part contributes (>1 symbol, or 1 symbol + hunk
   signals). Otherwise it is skipped and every later step shifts down by one.
5. **Signal ordering within a list is `|Points|` descending**, and zero-point
   signals are split into a separate collapsed "checked, not contributing"
   group (`SignalList`).

## Number formatting hazard (Go vs JS)

The arithmetic strings above come from JS `Number.toFixed(1)`, which rounds
**half away from zero**. Go's `fmt.Sprintf("%.1f", …)` uses **banker's
rounding** (half to even). These disagree:

| value | JS `.toFixed(1)` | Go `%.1f` |
|---|---|---|
| `0.25` | `0.3` | `0.2` |
| `1.05` | `1.1` | `1.1` |
| `6.85` | `6.8` | `6.8` |

The narrow-but-real divergence at exact ties is why the port should return
**raw `float64` values** and leave `.toFixed()` formatting in the frontend
(formatting is rendering, not math). If the Go side ever does emit
pre-formatted strings, it must implement JS `toFixed` semantics explicitly —
`fmt.Sprintf("%.1f", …)` is **not** a correct substitute.
