# Release v1.1.0

Date: 2026-10-26

## Summary

LiveReview v1.1.0 introduces the **Audit Log** — an enterprise-grade, tamper-evident record of every privileged action in your organization. It answers the questions security, platform, and compliance teams actually ask: *who did what, when, from where, and with what outcome?*

The release also makes GitHub onboarding a one-click experience, adds safer Managed AI configuration for Cloud admins, opens more of LiveReview on the Free plan, and ships the dependency and security updates from this cycle.

![LiveReview Audit Log showing live events, filters, actors, outcomes, and export actions](https://raw.githubusercontent.com/HexmosTech/LiveReview/master/docs/releases/assets/v1.1.0-audit-log.png)

*Reports → Audit Log: live tail, filters, per-event detail, CSV/NDJSON/evidence-package exports, and retention controls.*

## Why this matters

Before v1.1.0, answering "who changed this role?", "which API key was used?", or "did anyone export customer data last month?" meant stitching together server logs, database rows, and memory. The Audit Log turns that into a first-class, searchable product surface — with the integrity guarantees and export formats that audits and incident reviews require.

It is **on by default**, needs no extra infrastructure, and uses the database and blob storage you already run.

## What's new

### Audit Log: compliance-grade visibility, built in

- **Every privileged action, in one place.** Sign-ins (including failures), user and role changes, API-key lifecycle, billing, organization settings, integrations, repositories, reviews, exports, and AI/model calls are recorded with actor, source, IP, request ID, and outcome.
- **Append-only by construction.** PostgreSQL triggers reject `UPDATE`; deletes are refused unless the retention job explicitly opts in. A compromised handler cannot quietly rewrite history.
- **Tamper-evident hash chain.** Events are linked per organization with SHA-256, and a daily anchor records the chain tip. Super admins can verify an organization's chain in one click and see the first broken sequence and reason if anything was altered.
- **Scoped visibility that matches your role model.** Members see only their own actions. Owners see everything in their organization. Super admins see everything, including cross-org support work — while actions performed in super-admin capacity are intentionally hidden from owners.
- **Fast investigation.** Live tail (5-second polling, paused when the tab is hidden), 24-hour / 7-day / 30-day / 90-day / custom ranges, and filters for category, action, outcome, actor email, and free text. Open any row for sanitized details JSON, request ID, IP, user agent, and hash-chain sequence.
- **Retention you can defend.** Monthly partitions make retention cheap. Defaults are 90 days instantly searchable and 365 days total; a super admin can change both. Months beyond the hot window are archived to your configured blob store and downloadable from the page.
- **Evidence-friendly exports.** Export exactly the filtered view as CSV or NDJSON, or download an **evidence package**: a zip containing `audit.ndjson` and a `manifest.json` with row count, date range, organization, and SHA-256 digest.
- **AI usage, without exposing prompts.** The AI usage tab records provider, model, operation, token counts, cost, actor, and review. Raw prompts and responses are never stored — chat turns contribute only a prompt fingerprint and size.
- **SIEM-ready contract.** Action names are stable and documented in `docs/audit-events.md`, so Splunk, Datadog, and SIEM queries do not break between releases.
- **Least-privilege API access.** Normal API keys cannot read audit data. Owners can create an `audit_reader` key specifically for audit exports and integrations; cross-org admin reads remain session-only.
- **Your existing history is not lost.** The upgrade imports the existing user-management audit trail, so the new page is populated from day one.

### One-click GitHub onboarding (LiveReview Cloud)

- **Continue with GitHub** now installs the LiveReview GitHub App on the repositories you choose and signs you in on the same GitHub screen — no personal access token, no webhook setup.
- **A guided first run** shows connected repositories by GitHub account, helps configure AI, and leads to the first real pull request review in about two minutes.
- **Shared installations, without invites.** If a teammate already installed the app on a GitHub organization, another LiveReview organization can connect that installation and use the repositories its GitHub account can access. No need to reinstall or ask for an invite.
- **Clear ownership and safety.** Owners can connect, disconnect, or uninstall an installation; uninstalling warns how many other LiveReview accounts are affected. Repository access always respects GitHub's own permissions.
- **Returning users land in the right place** — the GitHub App card in Git Providers when their organization is already connected, or the next-step page when something still needs connecting.

### Managed AI: test before it touches a review (Cloud super admins)

- Configure the **main model** and **helper model** separately, with the same searchable model picker used in AI Providers.
- **Test and add**, **test and save**, and **activate** only succeed if the model actually answers. A bad key or retired model can no longer silently break reviews.
- New configurations start inactive; switching tiers is one click and the previous configuration stays available for rollback.
- Gemini Enterprise / Vertex AI and Gemini 3.x are supported, including the region rules Gemini 3.x requires.
- Paid organizations — and Free organizations created through the launch-trial link — can run reviews on the **LiveReview AI Model** without bringing their own key.

### More on the Free plan

- Free-plan organizations can now start reviews from the **web UI**, connect **git providers**, and add **up to 3 active members**.
- Launch-trial organizations get the LiveReview AI Model with a **30,000 reviewed lines per month** allowance, so a new team can see value before adding an AI key.

### Deployment and operations

- `lrops.sh setup-production --express` is now a **fully non-interactive production install**: generated secrets, reverse proxy enabled, webhooks enabled, no prompts. Demo express mode keeps its localhost-only defaults.
- `LIVEREVIEW_BIND_ADDR` lets you bind the app's published ports to a specific interface (for example `127.0.0.1` behind a reverse proxy) instead of every interface.
- Container detection and the production compose files were refined for more reliable upgrades.

### Security and reliability

- Updated Echo to v4.16.1 and refreshed `dompurify`, `ip-address`, `mcp`, and `Werkzeug` to clear published advisories.
- Cleared the CodeQL, gitleaks, govulncheck, OSV, and Semgrep findings from this cycle before shipping.
- Added a local end-to-end harness covering real accounts, isolated `lrc` reviews, audit scoping, URL checks, and the Audit Log UI — so release verification exercises the same paths customers use.

## Install and Update

- Install or update to the latest release:

```bash
curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
```

- Pin this exact version:

```bash
curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.1.0
```

- New production install with no prompts:

```bash
lrops.sh setup-production --express
```

The database migration runs as part of the update. It creates the partitioned audit tables, the append-only guard, the archive index, and the default retention policy. The database user must be able to create tables, triggers, and partitions (the same permission the existing migrations already require).

## Changes

- **Audit Log**: new `/reports/audit` page and org-scoped read APIs; live tail, filters, facets, event detail, CSV/NDJSON/evidence-package export, monthly archive download, retention metadata, AI usage tab, and super-admin cross-org/integrity/retention APIs.
- **Audit framework**: automatic HTTP middleware coverage for every non-GET API call; semantic, fail-closed audit events inside privileged transactions; sanitizer that strips secrets, tokens, passwords, cookies, and raw query strings; per-org SHA-256 hash chain and daily anchors; monthly partition maintenance and archive/prune jobs.
- **Visibility**: members see their own events, owners see their organization, super admins see everything; admin-capacity actions are hidden from owners. Audit reads require a session or an `audit_reader` API key.
- **Compatibility**: existing `user_management_audit` rows are imported as legacy history with `source='legacy'`; IP and user-agent columns are null for those older rows.
- **GitHub**: Continue-with-GitHub onboarding, shared GitHub App installations across LiveReview organizations, guided get-started page, connect/disconnect/uninstall controls, and clearer ownership messaging.
- **Managed AI**: main/helper tiers, provider/model picker, test-before-save/activate, inactive-by-default configurations, Gemini 3.x and Vertex support, and LiveReview AI Model routing for paid and launch-trial organizations.
- **Free plan**: web-UI review creation, git providers, and up to 3 active members; launch-trial AI allowance of 30,000 reviewed lines per month.
- **Deployment**: non-interactive `setup-production --express`, `LIVEREVIEW_BIND_ADDR`, and improved container detection.
- **Dependencies**: Echo v4.16.1, `dompurify` 3.4.17, `ip-address` 10.7.4, `mcp` 1.30.0, `Werkzeug` 3.1.9, plus npm overrides for `body-parser`, `fast-uri`, `serialize-javascript`, `undici`, `zod`, and `follow-redirects`.
- **Quality**: local E2E harness with isolated `lrc`, real accounts, audit-scoping tests, URL checks, and Playwright UI coverage.

## Breaking Changes

- **Audit logging is enabled by default for every organization.** Defaults are 90 days hot / 365 days total, with archiving anchored to your configured blob store. No action is required, but super admins should review the policy in **Reports → Audit Log → Retention** if your compliance window differs.
- **Standard API keys cannot read audit data.** Create a dedicated `audit_reader` key for SIEM or export automation. Cross-org admin audit reads are session-only.
- **The upgrade adds audit tables, triggers, partitions, and a daily maintenance job.** Run the normal `lrops.sh` update path so the migration applies; do not skip database migrations.
- **GitHub App, Managed AI, Free-plan entitlements, and launch-trial AI routing are LiveReview Cloud features.** Self-hosted installations still get the Audit Log and the deployment improvements, and continue to use their own AI provider configuration.

## Verification

```bash
livereview --version
lrops.sh --show-latest-version
```

Then, as an owner, open **Reports → Audit Log** and confirm that recent sign-ins and settings changes appear. As a super admin, open **Retention** and run **Verify chain** for your organization.

## Known Issues

- Archiving and pruning run on the daily maintenance schedule (03:15 UTC by default). The first monthly archive becomes available after that cycle, not immediately after upgrade.
- Only the existing user-management audit history is imported during the upgrade. Other historical actions from before v1.1.0 cannot be reconstructed; new events are captured from the moment the upgrade completes.
- Gitea has not been tested end to end with auto-approve yet.
- Owners intentionally cannot see actions performed in super-admin capacity; use a super-admin session for cross-org support investigations.
