# Release v1.2.0

Date: 2026-10-31

## Summary

This release is headlined by enterprise Single Sign-On — login via Okta, Azure AD,
Google Workspace, or Keycloak, plus SCIM-based user deprovisioning for self-hosted
deployments. Alongside that: findings now stream into the review page live instead of
appearing all at once at the end, you can get a browser notification when a review
finishes, the Auto Approve panel has been redesigned, and there's a new account menu
for self-service profile/password management. Several smaller UX papercuts (table rows
that didn't fully act as links, GitHub App connection quirks, dashboard empty states)
are also fixed, along with a risk-scoring accuracy bug that could pin a review's risk
score at an uninformative 100%.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.2.0

## Changes

### Enterprise Single Sign-On (OIDC + SAML), for self-hosted deployments

Self-hosted orgs on the enterprise plan can now let their team log in through their
existing identity provider — Okta, Azure AD, Google Workspace, Keycloak, or any
standards-compliant OIDC/SAML provider — instead of a separate LiveReview password.
Configure it once per organization from **Settings → SSO**, and a "Continue with…"
button appears on the login page automatically.

### Offboarding that actually works: session revocation + SCIM provisioning

SSO login is only half the story — this release closes the other half: when someone
leaves, LiveReview now finds out and locks them out, automatically, in several
layers:

- **Deactivating a user now really deactivates them.** Clicking "Deactivate" in
  Settings immediately revokes every one of that person's active sessions — their
  next request is rejected, not just their next login.
- **SCIM 2.0 provisioning.** Point your identity provider's SCIM app config at
  LiveReview (one generated token, **Settings → SSO → SCIM Provisioning**) and
  disabling someone in Okta/Azure/Google deprovisions them here automatically,
  usually within a minute.
- **Reconciliation polling**, for OIDC orgs that don't use SCIM: LiveReview can
  periodically double-check (hourly/daily/weekly, your choice) that every signed-in
  user is still active with the identity provider, and deactivate them if not.
- **Instant logout via OIDC back-channel logout**, for identity providers that
  support pushing a real-time logout signal.

### Findings stream in live, instead of waiting for the whole review to finish

Previously, starting a review bounced you to a log-style Events tab, and the Findings
tab stayed empty until the entire review completed — for a large pull request, that
could mean a long wait with no visibility into what was actually being found. Now:

- Findings is the default tab from the moment a review starts.
- The file/hunk list appears as soon as the diff is parsed — before any AI output
  exists yet.
- Comments appear inline in the matching file the moment each batch finishes, with no
  need to refresh.
- A "Findings are streaming in…" banner makes clear more is still coming.
- If a review fails partway through, everything found so far stays visible instead of
  being replaced by a generic error screen.

### Browser push notifications for review progress

You can now get a real, OS-level browser notification — even if the tab or browser
itself is closed — when the first finding becomes available, and again when a review
completes (or fails). Turn it on from the banner on any review page, or manage both
notification types independently from the new **Settings → Notifications** tab.

### Redesigned Auto Approve panel, with review times in your local time zone

- The per-review Auto Approve tab is reorganized onto one clean, aligned grid, with
  clear pass/fail/skip status icons and a bolder final decision line.
- Owners and admins get a direct **Configure** link from each stage straight to that
  stage's settings.
- The PR/MR description's review controls now sit in their own block at the top,
  separate from the auto-approval decisions table at the bottom.
- The decisions table now shows **when** each review ran, displayed in the time zone
  of whoever started it.

### Account menu, with self-service profile and password management

- The navbar's bare logout icon is now a proper account menu with your avatar
  (consistent initials and color, so it never changes across sessions), with quick
  links to your profile, password, and API keys.
- A new **Account** tab (`Settings → Account`) lets anyone update their own name and
  change their own password — no admin needed, and no API key can perform either
  action, only an authenticated session.
- The organization switcher now pins your current org clearly at the top, and role
  labels display correctly ("Super Admin" instead of a mangled "Super_admin")
  everywhere a role is shown.

### More accurate risk-based auto-approval scoring

Large, high-blast-radius changes could previously score a flat, uninformative 100%
risk — "maximally risky" regardless of how much riskier one huge PR actually was than
another. The underlying scoring model has been corrected so it continues to
meaningfully differentiate large diffs from each other instead of saturating at the
ceiling, with a safety net in place so this class of bug can't silently recur. This
also fixed a related cosmetic glitch where the risk indicator on a review page could
briefly flash the wrong risk level before settling on the correct one.

### Smaller fixes

- Clicking anywhere on a row in the Reviews, Repositories, or Pull Requests tables now
  opens that row — previously, "Open in new tab" only worked on a narrow strip of
  text inside each cell.
- Fixed duplicate PR comments and doubled pull requests appearing when the same
  repository was connected to LiveReview more than once.
- You can now connect your GitHub App installation without having to switch GitHub
  accounts first.
- GitHub webhook "ping" events are now answered correctly instead of returning an
  error.
- Dashboard cards with nothing to show now render a compact empty state instead of
  wasted blank space, and the Review Pipeline card shows a clear empty state when a
  repository's reviews found no issues.

## Breaking Changes
- None. SSO, SCIM, and push notifications are all additive and off by default until
  configured.
