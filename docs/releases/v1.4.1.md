# Release v1.4.1

Date: 2026-11-22

## Summary
- This patch republishes the v1.4.0 feature set from the `master` branch, so
  the published image and the mainline commit are the same code.
- **Cross-repo impact reaches CLI reviews:** a changed function that calls a
  route exposed by one of your related repositories is shown with that
  repository's friendly name and the matched route.
- **Related repositories are visible:** linked repository names, route chips,
  version-match badges, and cross-repo branches in the impact charts.
- **Math Mode matches the scorer:** the breakdown explains the saturating
  `sqrt(sum of symbols)` roll-up, file-level signals, post-scoring cross-repo
  adjustments, and the scaling step.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.4.1

## Changes
- Rebuilt and republished from `master`, so the Docker image and the
  mainline branch are the same commit.
- **Cross-repo matching for CLI reviews:**
  `POST /api/v1/diff-review/:review_id/cross-repo/matches` accepts the
  outbound HTTP calls a CLI review observed locally and matches them against
  the routes already indexed for the review's related repositories. It is
  read-only, org-scoped, and bounded; matching, chain, and cycle logic lives
  in one shared package so the CLI path and the server-side worker cannot
  drift.
- **Faster, restart-safe related-repo reads.** A successful graph read is
  cached in process for ten minutes, each related repo is read with one graph
  query, and a `graph.json` written next to each checkout means a restarted
  API serves its first cross-repo request immediately (about 1.4s in our
  check, versus roughly 40s cold).
- **Related repositories in the review UI.** Blue underlined repository links
  with a `related repo` badge and an open-in-app arrow, visible route chips,
  method-aware exact matches, labelled chains and version matches, and
  related repositories drawn in the Sunburst and Flame graphs, including
  symbols with no local callers.
- **Related Repos settings.** The picker is multi-select, and the settings
  page explains what each related repository contributes.
- **Navigation.** Every mega-menu row is a real link (middle-click and
  open-in-new-tab work), and the menu closes correctly after modified clicks.
- **Math Mode parity with git-lrc.** Current reports show the saturating
  sqrt combine and any post-scoring cross-repo adjustment; older reports keep
  their original linear arithmetic.
- **Deploy fix.** `raw-deploy-backend` builds the backend as a package, so
  the embedded UI assets and OpenAPI spec are included.
- **Release safety.** Releases must now be cut from `master`; the version
  bump refuses to run on a feature branch, and the local security scanners
  must finish green before any release step.

## Breaking Changes
- None. The new endpoint is additive, and cross-repo matching is best-effort:
  organizations without related repositories configured see no change.

## Verification

- `lrops.sh --show-latest-version` reports `v1.4.1`.
- Open **Explore -> Repositories**, configure a related repository, run a

  should appear.

## Known Issues
- A related repository that is slow to index can still be left out of a
  single match: the request returns partial results rather than timing out,
  and the next request picks up the cached graph.
- Multi-hop chains only appear when the indexed repositories actually expose
  a second cross-repo hop; a single-hop chain is the common case.
