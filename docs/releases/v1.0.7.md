# Release v1.0.7

Date: 2026-09-12

## Summary
CI/CD Gates now has a proper GitLab CI integration, a fixed GitHub Actions
workflow, and fallback guidance for every other pipeline — plus a backend fix
for a race condition that could let a gate pass on a review that actually had
blocking findings.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.0.7

## Changes
- **Fixed a review-status race condition**: a review could briefly report `completed` before its findings were fully saved, so a CI/CD gate polling right at that moment could see zero findings and wrongly allow a build that actually had blocking issues.
- **Fixed the GitHub Actions gate template**: it now triggers a review and polls the exact review it just triggered, instead of looking it up by commit SHA — the old approach could pick up a different PR's already-completed review of the same commit and evaluate the wrong result.
- **Added a native GitLab CI pipeline template** to the CI/CD Gates Integration page (previously GitLab only had the generic cURL fallback).
- **Added setup guidance for Bitbucket Pipelines, Azure Pipelines, and other CI systems** via the plain cURL/Bash snippet, with a pointer to hand it to a coding agent for platform-specific translation.
- **Documented how to actually block the merge button** per platform (GitHub branch protection required checks, GitLab "Pipelines must succeed"), plus real gotchas: fork PRs not receiving secrets, GitLab's "Protect variable" excluding unprotected branches, and GitLab's 8-character minimum for masked variables.
- Cleaned up the CI/CD Gates Integration page UI: copy buttons, environment variables table, setup instructions, and tab layout.
