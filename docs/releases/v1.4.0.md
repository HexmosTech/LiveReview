# Release v1.4.0

Date: 2026-11-22

## Summary
- **Cross-repo impact now reaches CLI reviews.** A review created from the
  command line can show that a changed function calls a route exposed by one
  of your related repositories, with the related repo's friendly name and
  the route it matches.
- **Related repositories are visible, not just scored.** Repository names
  are links, routes appear as chips, version matches get a badge, and the
  impact charts draw cross-repo branches so you can see the boundary being
  crossed.
- **Cross-repo matching got fast and predictable.** The related-repo graph
  cache survives API restarts, and a cold match no longer pushes a request
  past the reverse proxy's timeout.
- **Math Mode now matches the scorer.** The score breakdown explains the
  saturating `sqrt(sum of symbols)` roll-up, file-level signals, post-scoring
  cross-repo adjustments, and the scaling step.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.4.0

## Changes
- **New endpoint for CLI cross-repo matching:**
  `POST /api/v1/diff-review/:review_id/cross-repo/matches`. It is read-only,
  org-scoped, and bounded: the CLI sends only the outbound HTTP calls it sees
  in its local code graph, and the server matches them against the routes it
  already indexed for the review's related repositories. The shared
  matching, chain, and cycle logic now lives in one package, so the CLI path
  and the server-side worker cannot drift.
- **Related-repo matching reuses cached indexes.** A successful graph read is
  cached in process for ten minutes, the CLI path reuses an existing index
  instead of re-fetching, and each related repo is read with one graph query
  rather than several. Warm requests answer in under a second.
- **The related-repo graph cache survives restarts.** A `graph.json` written
  next to each checkout means a restarted API serves its first cross-repo
  request immediately (about 1.4s in our check, versus roughly 40s cold).
- **Related repositories in the review UI.** Related repo names are blue
  underlined links with a `related repo` badge and an open-in-app arrow;
  routes appear as visible chips; exact route matches are method-aware;
  chains and version matches are labelled; the Sunburst and Flame graph
  impact charts draw related repositories, including symbols with no local
  callers. Clicking the signal text opens the related repository.
- **Related Repos settings.** The picker is now multi-select, and the
  settings page explains what each related repository contributes.
- **Navigation.** Every mega-menu row is a real link (middle-click and
  open-in-new-tab work), and the menu closes correctly after modified clicks.
- **Math Mode parity with git-lrc.** Current reports show the saturating
  sqrt combine and any post-scoring cross-repo adjustment; older reports keep
  their original linear arithmetic so historical reviews still explain
  themselves correctly.
- **Deploy fix.** `raw-deploy-backend` builds the backend as a package, so
  the embedded UI assets and OpenAPI spec are included and the target no
  longer fails with undefined symbols.

## Breaking Changes
- None. The new endpoint is additive, and cross-repo matching is best-effort:
  organizations without related repositories configured see no change.

## Known Issues
- A related repository that is slow to index can still be left out of a
  single match: the request returns partial results rather than timing out,
  and the next request picks up the cached graph.
- Multi-hop chains only appear when the indexed repositories actually expose
  a second cross-repo hop; a single-hop chain is the common case.
