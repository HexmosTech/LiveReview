# Release v1.2.1

Date: 2026-11-06

## Summary

This release is headlined by **Force Approve** — a new manual override for reviews
blocked by Auto Approve policy — plus a major overhaul of how LiveReview surfaces
broken Git provider connections: instead of a flood of per-repository errors, you
now get one clear, actionable banner per connector, with a direct link to fix the
credential. Behind the scenes, a production incident where unauthenticated
repositories were silently retried tens of thousands of times a day (bloating the
job queue) is fixed with proper backoff and deduplication. There are also smaller
fixes: connecting GitHub no longer leaves you with a confusing extra browser tab,
the LiveReview logo now renders correctly in invitation emails and on login pages,
and a storage settings label has been clarified.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash

## Changes

### Force Approve: a manual override for blocked reviews

When Auto Approve's risk policy blocks a review, an authorized reviewer can now
step in and force-approve it directly from the Auto Approve panel, with a
required reason recorded for the override. Once force-approved, the panel clearly
marks the review as "force-approved by an authorized reviewer" so the history
stays transparent, and the action is safely idempotent — retrying it (e.g. after
a flaky network request) never double-applies the override.

### Connector health: one clear banner instead of error spam

Previously, if a Git provider credential expired or a connector stopped working,
every affected repository could surface its own error, burying the actual
problem. Now:

- **One banner per connector**, not one per repository, even if dozens of repos
  share the same expired token.
- Each banner states plainly what's wrong (e.g. "Your GitHub provider credential
  expired, please renew it"), how many repositories are affected, a direct link
  to renew the credential, and a link to the relevant setup guide.
- The same alert also appears in the notification bell and as a toast, with the
  same "fix it now" action.
- The Repositories table's sync-error tooltip now shows the actual reason a sync
  failed, not just "last synced: never."

### Fixed a production issue that could silently overload the job queue

A repository with an invalid or revoked Git provider token could previously be
retried continuously in the background — in one real incident, broken
connections generated hundreds of thousands of retry jobs a day, bloating the
database and slowing the whole system down. Broken repositories now back off for
several hours before being retried again, and duplicate sync jobs for the same
repository are no longer queued on top of each other. This is an internal
reliability fix with no action needed on your part.

### Smaller fixes

- Connecting a GitHub repository or organization now opens GitHub in a new tab
  with a clear "you can close this tab and refresh" banner, instead of silently
  reusing or confusingly duplicating your LiveReview tab.
- The LiveReview logo now displays correctly in organization invitation emails
  (previously blocked by some email clients) and uses the correct horizontal
  logo with tagline on login pages.
- The storage settings label "Preloaded Changes Archival" has been renamed to
  the clearer "Raw Diff Archival."
