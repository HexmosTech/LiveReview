# Release v1.4.2

Date: 2026-11-22

## Summary
- **ONNX-backed features no longer depend on a deleted repository.**
  `microsoft/onnxruntime` and its release downloads went 404, which meant a
  fresh install silently lost product-guidance document retrieval (Livi) and
  dropped the analytics schema index to lexical-only search. The runtime
  library is now resolved from an ordered source list and cached locally.
- **Same version on the fallback path.** The mirror is pinned to the same
  1.29.0 release as the primary, with its own checksums and archive layout, so
  falling back does not change which ONNX Runtime actually runs.
- **Resolution is logged.** Boot logs now state the source tried, the 404 or
  other failure, the source that worked, the verified/extracted member, the
  final path and whether it was a cache hit.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.4.2

## Changes
- **Ordered runtime sources.** `internal/docindex/embedder.go` resolves the
  onnxruntime shared library from Microsoft's release assets first, then the
  `csukuangfj/onnxruntime-libs` mirror at the same 1.29.0 release. Each source
  carries its own pinned SHA-256, size and archive member path; a source that
  404s, fails its checksum or cannot be unpacked is skipped for the next one,
  and the joined failure is reported only when every source fails.
- **Cache before network.** A library cached from any source is preferred over
  any download, so existing installations keep using the file they already
  have and new downloads happen at most once.
- **Archive support.** The mirror publishes `.zip` and `.tar.bz2` archives with
  unversioned library names, so `.tar.bz2` extraction was added and member
  paths are now per source instead of per platform.
- **dbctx reuses the same library.** The API resolves the library once at boot
  and exports it as `DBCTX_ONNXRUNTIME_LIB`, so dbctx's semantic scorer uses
  the resolved file instead of attempting its own (now dead) download. The
  schema-index build waits for that hand-off, bounded to 20 seconds so an
  unreachable host cannot delay it indefinitely.
- **Logging.** Resolution logs cache hits with their source, each fetch
  attempt with URL/size/rank/fallback flag, each failure, archive verification,
  the installed path and elapsed time, and an explicit line when an operator
  supplies the library via `DBCTX_ONNXRUNTIME_LIB`. Model weights and
  vocabulary follow the same cached-vs-downloaded pattern.
- **Regression tests.** Offline tests cover cached-copy preference, mirror
  fallback, per-source checksum rejection, all-sources-failed reporting,
  `.tar.bz2` extraction, and the completeness of every platform's source list.

## Breaking Changes
- None. The resolution is lazy and unchanged in shape: if every source fails,
  docindex builds without retrieval and dbctx stays lexical-only, exactly as
  before, and startup still succeeds.

## Verification
- `livereview --version` reports `v1.4.2`.
- `lrops.sh --show-latest-version` reports `v1.4.2`.
- With an empty `~/.dbctx`, boot logs show the primary 404, the mirror
  download and verification, the installed path, and the exported
  `DBCTX_ONNXRUNTIME_LIB`.
- Livi answers a documentation question using retrieved guidance pages, and the
  analytics schema index reports `semantic_ran=true` for a schema question.

## Known Issues
- `windows/arm64` falls back to the mirror's 1.31.0 build, because the mirror
  never published a dynamic 1.29.0 arm64 library. The version actually used is
  always stated in the resolution log.
- Running `make prep-dbctx` by hand, outside the server process, still uses the
  dbctx CLI's own now-dead download URL; set `DBCTX_ONNXRUNTIME_LIB` for that
  path until the dependency is updated.
