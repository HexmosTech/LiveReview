# Release v0.0.52

Date: 2026-09-01

## Summary
- **Fixes self-hosted Docker installs**, which crash-looped on startup in v0.0.51. If you are on v0.0.51, update to this release.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/main/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/main/lrops.sh | bash -s -- --version=v0.0.52

## Changes
- Fix the application container restarting forever on a fresh self-hosted install. The container failed to create its blob storage directory on the mounted data volume and exited, repeatedly:
  - `mkdir: cannot create directory '/app/lrdata/blobs': Permission denied`
- Fix the container health check, which queried an endpoint that does not exist (`/api/health` instead of `/health`) and so never reported healthy under plain `docker run`.
- Restore prompt, unbuffered log output from the container, so `docker logs` shows startup progress as it happens instead of in delayed chunks.
- Consolidate the two Docker build files into one. `Dockerfile` was unused by every build path and had silently diverged from `Dockerfile.crosscompile`, which is what release images are actually built from; the above fixes had previously been applied only to the unused file. It has been removed so future fixes cannot land in a file that never ships.

## Breaking Changes
- None.

## Verification
- livereview --version
- lrops.sh --show-latest-version
- After install, confirm the app container stays up rather than restarting:
  - `docker ps` — `livereview-app` should report `Up`, not `Restarting`
  - `curl -f http://localhost:8888/health`

## Known Issues
- Hosts that still have the legacy Compose v1 (`docker-compose`, 1.x) installed can generate a malformed `DATABASE_URL` at install time, causing migrations to fail with:
  - `pq: wrong value for "sslmode": "disable@livereview-db:5432/..." is not supported`
  - Compose v1 does not support the nested variable default used in the generated `docker-compose.yml`. Workaround: recreate the app container using Compose v2, which renders it correctly:
    - `cd ~/livereview && docker compose up -d --force-recreate livereview-app`
  - Note the space: `docker compose` (v2 plugin), not `docker-compose` (v1).
