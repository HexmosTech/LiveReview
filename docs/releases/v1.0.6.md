# Release v1.0.6

Date: 2026-09-11

## Summary
- Fixes Livi, the in-app assistant, giving wrong answers about onboarding team
  members and self-hosted licensing. Its route documentation was audited against
  the actual code: several pages overstated who can see them (claiming
  super_admin-only for tabs org owners can also use), the Onboarding Report was
  described as a per-person setup checklist when it is an org-wide analytics
  report, and the customizable dashboard widget grid was not documented at all.
- Per-seat licensing is retired from the documentation. Owners add unlimited
  users in User Management; no seat purchase or assignment step. Self-hosted
  licensing questions now point to the Hexmos team directly (info@hexmos.com,
  shrijith@hexmos.com), plus a new contact page covering Discord, Slack, and
  Teams.
- Release tooling now runs every image build, tag, and push on a dedicated
  `livereview` Docker context rather than whatever `default` happens to be, and
  fails fast with a clear message if GHCR login is missing.

## Install and Update
- Install/update script:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash
- Pin a specific version:
  - curl -fsSL https://raw.githubusercontent.com/HexmosTech/LiveReview/master/lrops.sh | bash -s -- --version=v1.0.6

## Changes
- Livi route docs: correct access gating for the Instance, Storage, Deployment,
  SMTP, and License settings tabs and for Reports (any org member can load them;
  only the Reports menu entry is owner/admin-gated).
- Livi route docs: rewrite the Onboarding Report page to describe what it is - a
  57-chart org analytics report across adoption, repositories, engineers,
  quality, cost, and engagement, with async PDF/HTML export. The per-person setup
  checklist lives on the Dashboard.
- Livi route docs: document the Dashboard's 13-widget grid - period selector,
  per-user layout, and how to read each chart (Sankey, treemap, radar, sunburst,
  coverage gauge, contribution heatmap, etc.) and where it drills through.
- Livi route docs: document the Taxonomy Reports modes, URL filters, and
  CSV/XLSX/PDF exports; replace the Integrations stub with the real Slack,
  Microsoft Teams, and Discord setup steps.
- Livi route docs: mark seat-based pages (License Management, Plan & Usage,
  Subscribe) as legacy and remove seat assignment from the onboarding path.
  Retire the per-seat route docs that no longer apply.
- Livi route docs: add a contact page and link 15 pages to the matching public
  documentation at hexmos.com/livereview/docs.
- Settings -> Integrations: remove the Livi icon download step from the Teams
  flow (branding comes from the uploaded app package) and fix the step numbering,
  which skipped 5. Azure Portal link normalized.
- Release tooling: all `docker` build/tag/push/manifest commands in
  `scripts/lrops.py` use a named `livereview` context, auto-created on first use.
  New `make ghcr-login` sets up the context and logs it in to GHCR via the gh
  CLI. When pushing, a missing login now fails in seconds with the exact command
  to run, instead of after a full multi-arch build.
- Release tooling: the multi-arch builder is renamed `livereview-multiarch`. A
  silent fallback that could pick up an unrelated builder is removed.
- Docs: the end-to-end release process (tag, GHCR login, notes, multi-arch build,
  GitHub release) is documented in `AGENTS.md`, including the interactive and
  non-interactive build variants, the `.env.selfhosted` prerequisite, and
  disk-space and build-context gotchas.
- Remove the legacy `livereview_pgdata` symlink from the repo root.

## Breaking Changes
- None for self-hosted deployments. Release operators need to run
  `make ghcr-login` once per machine; the old `gitlab` Docker context is no
  longer referenced.
