LiveReview empowers you to customize the review process to fit your team's working style. As of writing - you can include:

1. Style Guide
2. Security Guidelines

These are set at a organization level as of now - but we plan to support more granular level of application context as well (group/team/repo/language/framework/etc)

## When to use this vs. Repository Rules

Custom Prompts apply to every repo in your org, so keep them to standards that are genuinely universal across teams. If a rule only matters to one repo, use [Repository Rules](/livereview/docs/git-lrc/configure/repository-rules) instead — most teams should start there, since each team can scope its own rules without affecting anyone else's repo.
